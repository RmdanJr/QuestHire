# Dev environment gotchas (learned in this project)

The developer machine is **Windows with PowerShell 5**. These cost real time once; follow them.

## PowerShell and the shell tool
- **Refresh PATH** before using tools installed during the session (`gh`, `aws`):
  `$env:Path = [Environment]::GetEnvironmentVariable('Path','Machine') + ';' + [Environment]::GetEnvironmentVariable('Path','User')`
- **Native stderr is not an error.** git and gh print progress to stderr, which PowerShell shows as `NativeCommandError` even on success. Run them as `cmd /c "git push 2>&1"` and judge success by `$LASTEXITCODE` or by checking state (for example `git ls-remote`).
- **Long one-line commands sometimes come back empty or garbled.** Split work into small calls, and verify the result with a follow-up read (list the PR, the job, the branch) instead of assuming it worked. Retrying a create can fail because the first attempt already succeeded.
- **Write JSON for CLIs without a BOM:** `[IO.File]::WriteAllText($f, $json, (New-Object Text.UTF8Encoding($false)))`. `Set-Content -Encoding UTF8` adds a BOM, and the GitHub API then answers "Problems parsing JSON".
- **Nested quotes and `--jq` filters break inside `cmd /c`.** Prefer `gh ... --json` piped to `ConvertFrom-Json`, or save the output to a temp file and parse it in PowerShell.
- **`npm ci` can fail with `ENOTEMPTY` (errno -4051)** because of Windows file locking. Empty the folder with `robocopy <emptyDir> <target> /MIR`, delete it, then retry with `npm ci --ignore-scripts --prefer-offline --no-audit --maxsockets=2`. It is not a repo bug.
- To test like CI, copy tracked files to a short path (for example `C:\qhc`) with `git ls-files -co --exclude-standard`, then run the CI steps there. Delete the copy afterwards.
- Line-ending warnings (`LF will be replaced by CRLF`) are harmless.
- **`git add -A -- <paths>` after `git mv` can silently stage only the renames.** Check `git diff --cached --stat` before each commit when files were moved, and don't hide git's output.

## SonarQube Cloud
- **It skips dot folders** for code analysis (hidden files only go to the secrets scan). Scripts in `.kiro/skills/*/scripts/` are therefore not analysed by Sonar; we accepted that and rely on ESLint, tests and the coverage gate. Verified on PR #3: Sonar indexed 6 scripts in `scripts/` on `main` and none after the move to `.kiro`.
- Check what Sonar actually indexed with `https://sonarcloud.io/api/components/tree?component=RmdanJr_QuestHire&pullRequest=<n>&qualifiers=FIL`. A green gate on files it never indexed means nothing.

## Framework and tooling quirks
- **Next.js 16** is newer than most training data; read `node_modules/next/dist/docs/` first.
  - `LayoutProps`/`PageProps` are generated types, so `typecheck` runs `next typegen` before `tsc`. CI starts without `.next`, so never rely on a leftover build.
  - With `cacheComponents: true`, route segment config like `export const dynamic` is rejected. Use `await connection()` from `next/server` for per-request handlers.
  - `AGENTS.md` at the repo root is generated by Next.js. Leave it alone.
- **Prisma 7:** config lives in `prisma.config.ts` (with a placeholder URL so `validate` and `generate` work without a database); the client is generated to `src/generated/prisma` (gitignored). `prisma init` drops `.agents`, `.claude`, `.windsurf` and `skills-lock.json` into the repo; delete them. Keep `prisma` and `@prisma/client` on the exact same version (npm once picked an 8.0 release candidate).
- **Vitest config is ESM:** use `import.meta.dirname`, not `__dirname`.
- `npm install` warns about install scripts not covered by allowScripts; CI uses `npm ci --ignore-scripts` plus an explicit `npm run db:generate`.

## Kiro itself
- Agents cannot write to `~/.kiro/settings/` or `~/.kiro/workspace-roots/` (permission files). Give the user the content to paste instead of working around it.
- Hooks and new steering apply from the next session.
- Shell approval rules live in a `permissions.yaml` (deny > ask > allow); the old `trustedCommands` setting is gone in Kiro 1.x.
